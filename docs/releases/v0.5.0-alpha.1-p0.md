# Vastloom 0.5.0-alpha.1-p0 — post-conclusion P0 experiment

This tag is a post-conclusion experiment record on top of the frozen `v0.5.0-alpha.1` release. It
does not reopen the project, change its measured claims or add a throughput result.

## What this tag contains

- **Expert pack** (`vastloom.deepseek-v4-expert-pack.v1`): one contiguous, 4 KiB-aligned record per
  expert, built from the existing plans/artifacts by `tools/pack_deepseek_experts.py`, with source
  manifest and per-range SHA-256 provenance. The chain and layer probes accept `--expert-pack`.
- **Adaptive expert I/O**: `--io-cache buffered|bypass|auto`, with actual read-path counters
  (`bypass_read_calls` / `buffered_read_calls`) so a silent fallback is visible.
- **Measured effect**: token 0 reads 54 → 18 ranges, layer 0 18 → 6, five-token prompt 264 → 88,
  with byte-identical logits/hidden (argmax 86,051 / 30,528 / 20,267). Warm-cache timings were
  neutral; the direct-I/O proxy confirmed the bypass path but showed no wall-time win.
- **Bounded cache plan**: the chain emits `cache_plan` (range-slice resident floor, live headroom,
  128-entry ceiling, chosen entries) and `--cache-entries` fails closed outside it.
- **Recording-only usage profile**: `--usage-profile PATH` records per-layer/per-expert routing
  counts; it does not pin, place or preload experts.
- **Cold-cache helper**: `scripts/purge-standby.ps1`, elevated only; it was not executed on the
  reference host.

## Not claimed

No throughput or cold-cache result, no full model, no placement/pinning behavior, no VRAM payload
tier. The cold-cache reboot measurement remains missing because the reference process is not
elevated. The measured scope is one real layer and a three-layer hash-routed chain.
