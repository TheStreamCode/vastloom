# Vastloom TinyTransformer model format (`SGTMV001`)

## Purpose

`SGTMV001` is a deliberately small, bounded format used to validate Vastloom's native
model lifecycle and token-generation path. It is not intended to replace GGUF,
Safetensors or future model-specific packed formats.

The bundled `vastloom/tinychat-v1` fixture exercises:

- verified model loading;
- byte tokenization and prompt framing;
- causal attention with an incremental KV cache;
- MLP and residual execution;
- greedy and seeded stochastic decoding;
- streaming CLI output;
- safe rejection of malformed input.

## Byte order and scalar representation

- All integer fields are little-endian.
- Tensor values are IEEE-754 FP32 in little-endian order.
- The loader byte-swaps FP32 payloads on a big-endian host.
- Unknown flags or non-zero reserved fields are rejected.

## Fixed header

The file begins with a 96-byte fixed header.

| Offset | Type | Field |
|---:|---|---|
| 0 | `char[8]` | magic `SGTMV001` |
| 8 | `u32` | format version, currently `1` |
| 12 | `u32` | total header bytes including metadata |
| 16 | `u32` | feature flags |
| 20 | `u32` | vocabulary size |
| 24 | `u32` | context length |
| 28 | `u32` | model width |
| 32 | `u32` | layer count |
| 36 | `u32` | attention head count |
| 40 | `u32` | FFN width |
| 44 | `u32` | BOS token id |
| 48 | `u32` | EOS token id |
| 52 | `u32` | end-of-turn token id |
| 56 | `u32` | first byte-token id |
| 60 | `u32` | UTF-8 model-id byte count |
| 64 | `u32` | UTF-8 system-prompt byte count |
| 68 | `u32` | reserved, must be zero |
| 72 | `f32` | LayerNorm epsilon |
| 76 | `u32` | reserved, must be zero |
| 80 | `u64` | number of FP32 tensor elements |
| 88 | `u64` | tensor payload bytes |

Immediately after the fixed header:

```text
model_id bytes
system_prompt bytes
tensor payload
```

The declared total header size, tensor count, tensor bytes and physical file length must
all agree exactly. Trailing bytes are rejected.

## Flags

| Bit | Name | Meaning |
|---:|---|---|
| 0 | tied embeddings | token embedding is also the output projection; required in v1 |
| 1 | history support | adapter declares that its chat template supports conversation history |

The bundled fixture sets only bit 0 and is intentionally stateless.

## Vocabulary

The reference model uses 259 tokens:

```text
0  BOS
1  EOS
2  EOT
3..258  one token for each byte value 0..255
```

UTF-8 text is encoded as its raw bytes. Consequently, context accounting is exact in
bytes plus framing tokens rather than approximate subword tokens.

## Prompt framing

The native adapter formats one turn as:

```text
<BOS>S:{system prompt}
U:{user prompt}
A:
```

Generated byte tokens continue after `A:` until EOT, EOS, timeout or the context limit.
The committed validation model does not retain earlier turns.

## Architecture

TinyTransformer v1 is a pre-LayerNorm causal Transformer:

```text
token embedding + learned position embedding
  repeat N layers:
    x = x + attention(layer_norm(x))
    x = x + linear_2(gelu(linear_1(layer_norm(x))))
final layer norm
tied token-embedding output projection
```

Attention uses standard scaled dot-product causal masking. Native generation processes
one token at a time and retains per-layer keys and values.

## Tensor order

All matrices are row-major FP32. Tensors occur in this exact order:

1. token embedding `[vocab_size, d_model]`;
2. position embedding `[context_length, d_model]`;
3. for each layer:
   - `ln1.weight [d_model]`;
   - `ln1.bias [d_model]`;
   - `qkv.weight [3*d_model, d_model]`;
   - `qkv.bias [3*d_model]`;
   - `attention_projection.weight [d_model, d_model]`;
   - `attention_projection.bias [d_model]`;
   - `ln2.weight [d_model]`;
   - `ln2.bias [d_model]`;
   - `fc1.weight [d_ff, d_model]`;
   - `fc1.bias [d_ff]`;
   - `fc2.weight [d_model, d_ff]`;
   - `fc2.bias [d_model]`;
4. final LayerNorm weight `[d_model]`;
5. final LayerNorm bias `[d_model]`.

The output head reuses the token embedding and is not stored twice.

## Loader safety limits

The v1 loader rejects files outside the following implementation bounds:

| Item | Limit |
|---|---:|
| file size | 8 GiB |
| metadata | 1 MiB |
| vocabulary | 65,536 |
| context | 32,768 |
| model width | 4,096 |
| layers | 128 |
| heads | 128 |
| FFN width | 32,768 |

It also rejects:

- dimensions that do not satisfy the architecture contract;
- invalid or colliding special-token ids;
- a width not divisible by head count;
- tensor count/layout mismatch;
- truncated or trailing payload data;
- NaN or infinite weights;
- unsupported flags and versions.

Weights and generation workspace must each obtain a Resource Governor reservation before
allocation.

## Integrity model

The binary format provides structural integrity, not cryptographic identity. Production
use should pass a `.sgm` manifest to `vastloom chat`, `model-info` or `self-test` so the
file is SHA-256 verified before parsing.

A direct `.sgtm` path is supported for development but is reported as not manifest
verified.

## Reproduction

With PyTorch installed:

```bash
python3 tools/train_tiny_chat.py
```

The exporter validates five responses before atomically writing:

- the `.sgtm` model;
- the `.tests.json` vectors;
- the exact `.sgm` SHA-256 manifest.

On the alpha.2 validation host, two independent 600-step exporter runs produced a
byte-identical model matching the committed fixture. Determinism across different PyTorch,
compiler or hardware versions is not claimed.

Native inference has no PyTorch dependency.
